# Level Up — план разработки

Исходное ТЗ: геймифицированный трекер питания/активности в стиле RPG.
Этот документ фиксирует, **что мы из ТЗ реально делаем, в каком порядке и почему**.

## Главный принцип

Всё приложение держится на одной петле: **сказал → записалось → +XP**.
Если она укладывается в 10 секунд — остальное (квесты, магазин, гильдии) надстраивается.
Если нет — остальное не спасёт. Поэтому сначала делаем эту петлю целиком и вертикально.

## Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Репозиторий | Новое независимое приложение `levelup`, пишется с нуля | Код из других проектов не берём; стек выбран тот же, что уже знаком (Expo + NestJS) |
| Мобилка | Expo / React Native | Expo Go даёт мгновенный цикл разработки на iPhone без сборок; TS везде |
| Бэкенд | NestJS (тонкий) | Прокси к LLM — ключ нельзя класть в приложение; синхронизация |
| Телефон | iPhone, без платного Apple Developer | Сайдлоад: Codemagic собирает IPA → SideStore подписывает бесплатным Apple ID |
| LLM | Адаптеры: Claude Haiku 4.5 (дефолт), OpenAI, локальная Ollama | Один интерфейс, провайдер — настройка |

## Архитектура разбора еды

LLM **не считает калории**. Она только извлекает сущности:

```
"тарелка плова и два бутерброда с колбасой"
  → LLM →  [{dish: "плов", qty: 1, unit: "тарелка"},
            {dish: "бутерброд с колбасой", qty: 2, unit: "шт"}]
  → резолвер (наш код): поиск в базе блюд + порции пользователя ("моя тарелка = 300 г")
  → {items: [...], kcal: 890, protein, fat, carbs, questions: []}
```

- Вероятностная часть (LLM) проверяется **эталонным набором фраз** (eval).
- Детерминированная часть (резолвер, расчёт, XP) — обычными unit-тестами.
- Уточняющий вопрос задаётся, только если разброс калорий между трактовками велик
  (четверть плитки vs целая — 130 vs 530 ккал). Максимум 2 вопроса на запись.
- MealLog хранит снимок калорий/БЖУ, а не только ссылку на блюдо — правка базы
  не переписывает историю.

## Ограничения iPhone без платного аккаунта

| Что | Последствие |
|---|---|
| Подпись бесплатным Apple ID | Приложение живёт 7 дней, SideStore продлевает само; максимум 3 сайдлоад-приложения |
| Нет APNs | Удалённые push невозможны → **локальные уведомления** (напоминания, квесты дня) |
| HealthKit | Не факт, что entitlement переживёт переподпись → **проверить отдельным спайком на этапе 5**, запасной вариант — ручной ввод шагов/веса и импорт |
| Распознавание речи | `SFSpeechRecognizer` entitlement не требует — только описание в Info.plist |
| Нативные модули | Не работают в Expo Go → UI и игровую логику гоняем в Expo Go, нативное — через dev-сборку на Codemagic |

## Правки к ТЗ

1. **Скорость**: одна метрика вместо трёх — от тапа по микрофону до «Записано» ≤ 10 с в 80% случаев.
2. **«90% блюд»**: измеряется на эталонном наборе фраз, который пишется первым.
3. **Google Fit API закрывается** → Health Connect (если когда-нибудь будет Android).
4. **Умные весы** отдельно не интегрируем — Xiaomi/Withings пишут в Apple Health.
5. **Офлайн**: распознавание речи на устройстве работает, LLM — нет. Без сети фраза
   встаёт в очередь и разбирается при появлении связи. Шаблоны работают полностью офлайн.
6. **Безопасность (РПП)**: целевой вес не ниже ИМТ 18.5; XP за честную запись,
   никогда за «съел меньше нормы»; пропуск дня не наказывается жёстко.
7. **Аватар**: слои SVG/Rive, 3 стадии телосложения — без дорогого арта на старте.

## Этапы MVP

Каждый этап — один или несколько коммитов.

| # | Этап | Результат |
|---|---|---|
| 0 | Скелет монорепо + эталонный набор фраз (~50 штук) | Есть чем мерить качество |
| 1 | Парсер: LLM-адаптеры → JSON → резолвер → правило уточнений | Ключевая фича работает через API |
| 2 | База блюд СНГ, ~150 позиций | Плов, оливье, гречка с котлетой и т. д. |
| 3 | Мобилка: главный экран, микрофон, подтверждение, шаблоны, локальная БД | Можно записывать еду с телефона |
| 4 | XP / уровни / стрик — чистые функции в `domain` с тестами | Игровой слой |
| 5 | Спайк HealthKit на сайдлоаде → шаги/сон/вес | Пассивный сбор данных (или запасной путь) |
| 6 | Сборка IPA на Codemagic → SideStore | Приложение живёт на телефоне |

**После MVP**: ежедневные квесты, достижения, магазин и валюта, фото-ввод,
аналитика и графики. Социальные функции (гильдии, PvP, лидерборды) — последними:
они требуют аккаунтов и модерации.
